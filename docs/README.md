# 项目文档导航

这组文档保存《小动物餐厅》的产品目标、设计取舍和开发约定。新协作者先读本页，再按工作内容进入对应文档。

仓库根目录的 [`AGENTS.md`](../AGENTS.md) 是Codex等AI协作工具的自动上下文入口。它保存必须优先知道的产品边界，并要求AI按任务读取本目录中的详细资料。

## 先了解产品

1. [项目背景与共同认知](./PROJECT_CONTEXT.md)：项目缘起、儿童学习假设、家庭使用场景和不可破坏的原则。
2. [产品需求文档](./PRD.md)：当前已经确认并实现的功能范围，是判断产品行为的主要依据。
3. [产品与交互设计](./PRODUCT_DESIGN.md)：儿童端、家长端、视觉、文案和声音的设计规则。

## 开始开发

1. [技术架构](./ARCHITECTURE.md)：代码模块、状态模型、存储、音频和离线更新机制。
2. [协作开发指南](./CONTRIBUTING.md)：本地启动、修改流程、测试要求和提交规范。
3. [验收记录](./ACCEPTANCE.md)：已经验证的能力及仍需完成的真机、家庭试用项目。
4. [部署记录](./DEPLOYMENT.md)：Cloudflare Pages 发布信息、安装方式和线上故障记录。

## 理解取舍和后续方向

- [关键决策记录](./DECISIONS.md)：为什么采用当前方案，以及哪些决定需要讨论后才能改变。
- [产品路线与待评估方向](./ROADMAP.md)：双设备同步、批量生成家人语音等尚未进入当前版本的工作。
- [最初实现计划](./superpowers/plans/2026-09-21-animal-restaurant.md)：首版开发任务的历史记录，不再作为当前需求基线。

## 文档的更新规则

| 变化 | 需要更新的文档 |
| --- | --- |
| 改变儿童可见行为或家长设置 | `PRD.md`、`PRODUCT_DESIGN.md`、对应验收项 |
| 改变代码结构、数据格式或离线机制 | `ARCHITECTURE.md`、迁移说明、对应测试 |
| 做出影响范围或隐私的新决定 | `DECISIONS.md`，必要时同步 `PROJECT_CONTEXT.md` |
| 讨论中的设想准备进入开发 | 先在 `ROADMAP.md` 写清成功标准，再更新 PRD |
| 完成发布或发现线上问题 | `DEPLOYMENT.md`、`ACCEPTANCE.md` |

文档描述应区分“已上线”“已确定待开发”和“仍在评估”。不要把讨论中的想法直接写成当前能力。
