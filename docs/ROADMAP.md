# 产品路线与待评估方向

当前版本已经具备三种玩法、1～5数量、七种食物、逐句家人配音、语音包备份和PWA离线运行。近期工作应先验证真实家庭使用，再决定是否增加账号、服务端或生成式声音能力。

## P0：完成真实设备和儿童试用

- 在实际iPad Safari和小米平板Chrome完成安装、录音、断网启动和横竖屏验收。
- 在两台设备之间往返导出、传递和导入一份真实语音包。
- 完成三次短时家庭试用，记录孩子是否认得大虾、排骨和蔬菜，是否理解锅内数量、拿回和上菜。
- 根据观察调整图案、间距、语音长度和提示，不根据一次答对或答错自动改变难度。

P0完成前，不建议扩展经营、奖励或更多学习内容。

## P1：降低双设备转移录音的步骤

当前可行流程是：设备A导出语音包 → 使用系统分享、隔空投送、附近分享、聊天工具或网盘传递文件 → 设备B在家长区导入。这个方案不需要账号，录音不会经过项目自己的服务器。

优先改进这个流程：

1. 在支持Web Share API的设备上增加“导出并分享”。
2. 导出前显示角色、句数、日期和文件大小。
3. 导入后显示新增、替换和保留的句数。
4. 在不支持分享的浏览器继续提供文件下载。
5. 用真实iPad和Android验证分享文件能回到正确的PWA入口。

成功标准是家长不用理解JSON或浏览器存储，也能在两分钟内把一套录音复制到第二台设备。

## P2：评估自动同步是否值得引入后端

如果手动分享仍然频繁造成困难，再评估“配对码同步”。建议流程是设备A生成短时配对码，设备B输入后拉取加密语音包；服务端只保留短期密文，成功下载或到期后删除。

进入开发前必须先回答：

- 谁可以发起、覆盖和撤销同步？
- 两台设备都修改同一句时如何选择版本？
- 录音在传输和暂存中如何加密，多久删除？
- 没有网络、服务不可用或换浏览器时怎样恢复？
- 家长如何知道哪些数据离开了设备？
- 运维成本是否值得减少的操作步骤？

不建议为了家庭两台设备直接引入长期账号和永久云端录音库。

## P2：评估批量生成家人语音包

需求是家长录入一段普通语音，由系统用相同音色生成游戏所需的完整短句。它可以明显减少逐句录制，但当前H5不适合直接承担训练和批量生成：不同移动浏览器算力差异大，长任务容易被切后台中断，模型体积也会破坏离线准备体验。

建议先做独立的家长侧语音包制作流程：

1. 明确取得录音者本人授权，并说明用途、存储位置和删除方式。
2. 录制覆盖常见音节、语速和情绪的样本，并做环境噪声检查。
3. 在独立工具或受控服务中生成全部台词。
4. 家长逐组试听，单句可重生成或改回真人录音。
5. 转换为当前语音包格式，再导入两台平板。
6. 删除生成服务上的原始样本、模型和中间文件，保留删除结果。

评估指标包括：孩子是否听得像且舒服、数字和量词是否清楚、两种角色是否有合适的表演感、生成失败能否单句修正、总成本、等待时间、服务是否允许家庭非商业使用，以及录音和模型是否会被用于训练。

满足以下条件后才进入产品开发：

- 录音者可明确同意、撤回和删除。
- 全部固定台词可稳定生成，数字1～5和七种食物发音清楚。
- 生成结果由成人试听确认后才进入孩子端。
- 不把声音模型或服务密钥放进公开H5代码。
- 默认玩法在生成服务不可用时仍能正常运行。

## 暂不规划的功能

- 加减算式、组合订单和自动升难度。
- 金币、签到、排行榜、广告和内购。
- 儿童语音识别、持续监听或开放式AI对话。
- 用使用时长、答对率或错误次数生成能力报告。

新增方向先写清儿童价值、家庭成本、隐私变化和可验证的成功标准，再决定是否进入PRD。
