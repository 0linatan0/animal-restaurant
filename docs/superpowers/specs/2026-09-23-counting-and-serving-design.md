# 点餐余量与上菜核对设计

日期：2026-09-23。状态：用户已确认方向与设计并授权实现；已完成本地实现，待发布及真机试用。

## 已确认的方向

1. 保留准确份数的入门玩法，增加同一种食物有余量的点餐档位，让孩子自己决定何时停止取食。
2. 上菜后默认由小动物逐个数盘内食物，孩子可选择“我来数”；确认实际总量、核对订单后，再展示动物享用。

第三档减少图案提示尚未进入本次范围。分类玩法不变；自由厨房保留原有请客流程，本次新增核对与享用先用于动物点餐。

## 目标和边界

让孩子在请客情境中接触逐个计数、总量和按需取物。玩法不评估能力，不设置自动升级、正确率或速度奖励。学习效果需通过家庭共同游戏观察，不能从点击完成直接推断。

保留一单一种食物、不自动补货、盘子最多五个、触摸目标至少72×72 CSS像素、错误保留盘子、家长随时跳过或收工的规则。不新增账号、上传、儿童监听或第三方依赖。

## 点餐档位

家长区增加“备菜方式”：

| 档位 | 数量 | 初始食物 | 提示 |
| --- | --- | --- | --- |
| 一起装盘（默认） | 沿用1～5、1～3或指定数量 | 等于订单数量 | 沿用原设置 |
| 自己拿够 | 首轮设计限定1～3或指定1、2、3 | 订单数量加一个 | 固定完整图案、数字和语音 |

新档位先用少量余量试用，不增加干扰种类，也不同时减少提示。切换到“自己拿够”时，家长区明确显示数量范围；若原选项是1～5、4或5，改为1～3并显示说明，不能静默生成范围外订单。该档位不提供4、5和简化提示。设置在下次开局生效，原有存档默认属于“一起装盘”。

每轮食物仍有稳定ID；锅内和盘内食物互斥，两者合计始终等于本轮初始库存。上菜前，孩子可以拿多、拿回或提前提交；不能因达到目标数量而自动提交。

## 一轮完整体验

听订单 → 自由取放 → 孩子点上菜 → 数实际盘子 → 确认实际总量 → 核对订单 → 调整或享用 → 下一位客人／收工。

### 默认自动数

上菜进入独立核对阶段，保持盘内食物位置稳定，暂时停止取放，锅和订单仍可见。小动物说“我们来看看”，然后按盘内顺序指向每件物体，同步播放“一、二、三……”并留下序号标记。数过的食物不消失、不跳位。每个数词播放结束后再继续下一件，不重叠播放。

数完后突出整盘和总量，说完整短句，例如“总共三个饺子”。只有此后才展示与订单是否相符的反馈，绝不把订单目标数量当成实际数量朗读。

### 孩子选择“我来数”

核对开始即显示带点按图案的“我来数”入口；引导语说明可以点它自己数，不要求识字。孩子可在自动计数或总量播报期间切换：停止旧语音和自动动作，清除旧标记，从一重新开始这一遍计数。

孩子每点一个未数过的食物，只标记和播放一次；已数过的物体重复点不增加数量。当前数词播完前暂不接收下一件的计数点击，避免语音排队后落后于画面。所有食物数完后确认总量、核对订单。孩子无需口头回答，设备不监听。

手动计数时提供带动物图案的“帮我数”；选择后清空本遍标记，由动物从一重新数。无操作时安静等待，不自动接管；随时可以返回装盘或由家长跳过、结束，不把手动数完作为退出条件。

核对期间提供“继续装盘”返回入口，取消本次核对并清除标记。修改后的盘子需再次主动上菜。上菜前原有可选“数一数”继续保留，两种计数不共用旧标记。

### 核对和调整

| 实际情况 | 行为 |
| --- | --- |
| 空盘 | 直接说“盘子还是空的，拿一点食物吧”，回到装盘；不播放“一”，不进入享用 |
| 正好 | 确认实际总量，感谢，进入享用 |
| 少或多 | 先报实际总量，再重申目标并提示可以添加或拿回；回到装盘，保留食物 |
| 类型不符 | 正常点餐不生成此情况；若有效模型状态中出现，先说明实际总个数，再提示订单种类，不把混合食物称为同一种 |

例：目标三个、实际两个时，“总共两个饺子。我想吃三个，再拿一个吧。”差值不为一时使用“再拿一点”或“可以拿回去一些”，首版不扩展加减计算。沿用连续两次不匹配展开完整图案的帮助，不自动代答。

### 动物享用

数完并确认匹配后，盘子移动到动物面前；动物拿起食物、咀嚼、露出满足表情。食物只在此阶段逐个从展示盘消失，不伴随新的递增计数。动画约3～4秒，提供“跳过动画”入口，支持减少动态效果的静态替代。

享用是已提交订单的展示，不通过取放动作修改库存。跳过、动画完成都进入同一个幂等的轮次推进动作；不能重复算轮或多生成客人。最多三位客人，达到轮数后收工，不自动开新局。

## 状态、模块和中断

`model.js` 负责备菜规则、取放、核对阶段、计数模式和标记、核对结果、享用与轮次；DOM只分发动作。建议区分装盘、核对、享用、收尾阶段，在核对阶段记录自动／手动和当前步骤。

`app.js` 负责指物、序号、交互入口和动画呈现；`audio.js` 串行执行台词。语音／动画完成后分发模型动作，每次核对带独立标识；取消、切换计数、暂停、跳过后，旧完成回调不能推进当前流程。不得依靠固定语音时长决定下一步。

切后台立即停止声音、动画和计时，返回需主动继续。核对中恢复时保留盘子和订单，清除核对标记，从一重新计数，沿用自动或手动选择；享用中恢复显示已完成订单并允许继续／跳过展示，不能重新提交或重复计轮。刷新恢复同样遵循这些规则。达到时间上限或家长结束，任何阶段均可收尾；未完成订单不能描述成完成。

任何核对语音失败（引导、自动或手动数词、总量、调整反馈、感谢）均停止当前步骤，保留画面，提供恢复声音或无声继续，不直接当作正常播完。恢复声音仅重播失败短句；若食物已经标记，不重复添加标记或递增数值。选择无声继续时，当前步骤只完成一次并解除手动点击锁；后续数词以逐个可见标记和短暂指物停留代替声音，总量与反馈同步保留图案和文字，整轮沿用无声模式。自动逐个演示仍可切到手动，手动也可请动物帮助，不能因缺声音卡住游戏。恢复与无声完成均校验当前步骤标识，防止迟到的音频回调重复推进。动画失败或减少动态效果时可直接显示静态享用画面并继续。暂停后的旧声音不得重新播放。

核对和享用期间暂时禁用重听订单按钮，返回装盘后恢复。原有一分钟收工提醒若在核对或享用期间触发，延后至返回装盘或展示完成后的安全节点播放，最多一次，不插入计数、总量或感谢；若已经到达时间或轮次上限，则丢弃待播提醒并直接收尾。时间上限与家长结束的优先级高于所有语音和动画。

`catalog.js` 和 `parents.js` 增加需要的引导、总量与反馈完整台词及录音入口；优先复用原台词ID。新句子有内置音频，旧家庭录音继续有效，未录新句子回退默认音频。录音包格式本次不变，不上传家庭录音。

会话增加阶段和备菜设置需明确版本迁移；旧版准确份数会话按原档位恢复，旧的已提交状态不能重新核对或计轮。校验按档位核实库存、物体ID、盘内子集和计数标记，不接受不合法恢复数据。`storage.js` 仍只负责读写，迁移和验证在模型中完成。

## 实现时需同步的基线

当前PRD、产品设计、架构、项目背景与AGENTS.md均写明库存等于订单，D-006记录了这一取舍。实现新档位时同步改为“入门等量；自己拿够有固定余量；所有档位数量守恒”，并在DECISIONS.md记录扩展原因。

自动核对与原有手动数数必须在设计文档中分开说明，避免“所有计数只能由孩子点按”的旧描述与新行为冲突。代码和默认音频完成后重新构建，更新离线资源清单；本文件与路线图不代表功能已上线。

## 验证

- 模型：旧档位35种订单、新档位七种食物×三个目标数量；取放守恒、拿多拿少、空盘、重复计数、返回改盘、模式切换和失效回调。
- 恢复：旧设置与旧会话、核对中断、享用中断、重复动画完成、后台暂停、时间上限和家长跳过；旧核对回调在新核对开始后到达必须无效，享用完成与家长跳过同时到达只推进一轮。
- 浏览器：自动指物与语音同步、手动入口与回退、快速点按不漏报已接受的计数、错误保盘、享用和跳过、横竖屏触摸尺寸、音频失败恢复、默认音频完整和离线新页面启动。
- 实现后运行 `npm test`、`npm run build`、`npm run test:browser`；影响Service Worker逻辑时补充部署测试。
- iPad Safari和Android Chrome真机验证触摸、声音、后台返回和离线；家庭试用观察孩子是否理解锅里可留余量、是否愿意核对和是否理解享用阶段，不据此生成能力结论。

## 已确认的具体取舍

两个方向已确认。本文将首轮余量设为多一个、目标限定1～3、切换计数时从一重数、享用约3～4秒作为实现细节，用户已授权按本设计处理；享用实际时长为3.6秒。
