# 协作开发指南

仓库根目录的 `AGENTS.md` 会向支持该约定的AI开发工具提供项目背景。使用Codex时，应从仓库根目录或其子目录打开项目，使该文件进入任务上下文；AI仍需按任务读取本页列出的详细文档。

## 开始前先读产品边界

开发者至少阅读：

1. [项目背景与共同认知](./PROJECT_CONTEXT.md)
2. [产品需求文档](./PRD.md)
3. [产品与交互设计](./PRODUCT_DESIGN.md)
4. [技术架构](./ARCHITECTURE.md)

如果代码行为与PRD不一致，先判断是缺陷还是需求已经变化。不要在修复代码时顺便改变儿童反馈、难度或隐私边界。

## 本地运行

需要Node.js 20或更新版本。项目没有第三方运行时依赖。

```bash
npm run build
npm start
```

打开 <http://127.0.0.1:4173>。每次修改 `public/` 后重新构建，确保Service Worker版本和资源清单同步更新。

## 按一条完整体验修改

1. 在PRD或路线文档中确认需求状态。
2. 找到状态模型、界面、台词、存储和离线资源中受影响的部分。
3. 先维护游戏状态不变量，再修改呈现。
4. 对规则变化补充模型测试；对真实交互变化更新浏览器验收。
5. 更新受影响的文档和验收记录。
6. 在真实游戏尺寸检查触摸和食物辨认。

食材调整通常会同时影响：

- `public/js/catalog.js` 中的名称、量词和台词ID。
- `public/js/art.js` 中的插画。
- 两个角色的默认音频。
- Service Worker资源清单和版本。
- 旧会话、旧语音包兼容。
- 35种订单和浏览器流程测试。

不要只换一张图或一段文字就结束修改。

## 保持儿童体验约束

提交前检查：

- [ ] 孩子不识字也能理解主要任务。
- [ ] 核心目标不小于72×72 CSS像素。
- [ ] 点击可以完成操作，拖动不是唯一入口。
- [ ] 数量与可见物体一致，取放不会复制食物。
- [ ] 错误可以修正，没有扣分、催促或羞辱性反馈。
- [ ] 语音不重叠，切后台会停止。
- [ ] 达到时间或轮次后能自然收尾。
- [ ] 没有新增儿童监听、远程上传或第三方追踪。

## 运行与改动相匹配的验证

规则或数据结构变化至少运行：

```bash
npm test
npm run build
```

页面、触控、录音、备份或离线流程变化还要运行浏览器测试。涉及发布行为时运行部署测试，并按 `docs/ACCEPTANCE.md` 补充真机检查。

不要提交以下内容：

- `node_modules/`、`dist/`、`artifacts/`
- 家人真实录音包和浏览器导出数据
- Access Token、服务密钥或本机凭据
- 包含孩子姓名、影像或设备标识的试用记录

## 提交保持单一目的

提交信息使用中文，格式为：

```text
type(scope): 描述
```

常用类型包括 `feat`、`fix`、`refactor`、`docs` 和 `chore`。示例：

```text
fix(game): 保持点餐食物数量守恒
docs(product): 补充双设备语音包路线
```

这个个人项目的本地Git身份使用GitHub隐私邮箱。提交前可以检查：

```bash
git config --local user.name
git config --local user.email
```

不要把公司的姓名、邮箱或凭据写入个人项目提交。

## 提交变更说明

合作者的变更说明应包含：

- 孩子或家长会看到什么变化。
- 为什么这样改，以及对应哪条产品规则。
- 运行了哪些自动化和真机检查。
- 是否改变本地数据、语音包、离线缓存或部署方式。
- 仍需家庭试用确认的部分。
