# 项目背景与共同认知

## 这个游戏来自真实的亲子厨房游戏

《小动物餐厅》面向2～3岁儿童。最初的玩法是成人说“给我三个水饺”或“四个鸡翅”，孩子从一堆食物中找出对应种类和数量。H5版本把成人扮演的顾客换成小兔子和小熊，让孩子在做饭、请客的情境里接触分类、数字和数量。

这是一个家庭项目。家中有双胞胎，游戏会在iPad和Android平板上使用。成人通常在旁陪同；父母不在时，也可能由爷爷等其他照护者陪孩子玩。因此，界面必须让照护者容易理解，也不能假设两台设备自动共享数据。

## 数字符号、数量和数数是三个相关但不同的经验

孩子认识数字“3”的形状，不等于已经理解“三个东西”。她也可能会拿出三个饺子，但还不认识数字“3”。逐个点数时，还要慢慢建立“一件物体对应一个数词”和“最后一个数词代表总量”的经验。

游戏把这些经验放在同一份订单中：

1. 语音说出数量和食物。
2. 订单显示数字。
3. 完整提示显示对应份数的图案。
4. 孩子一次移动一个真实可见的食物。
5. “数一数”让每个物体只被计数一次。
6. 完成后再次说出总量。

这是一种日常接触和共同游戏，不是课程、测试或发展评估。答对率、完成速度和使用时长都不能用来判断孩子能力。

## 家人的声音是在扮演小动物

父母录音的目标是让小兔子或小熊带着熟悉的声音说话。动物角色仍然成立，录音不模拟父母正在实时对话，也不替代真实陪伴。

当前版本按完整短句录制。这样语气自然，也避免把单词机械拼接成订单。没有录制的句子使用同角色的内置声音，孩子随时可以继续游戏。

## 已从家庭试用得到的设计反馈

### 锅中的数量必须真实守恒

早期方案在取走食物后自动补充，容易让孩子看到的数量和正在操作的数量不一致。当前点餐模式只提供订单需要的准确份数。例如订单是“四只虾”，锅里就有四只；取走一只后锅里剩三只，拿回后才恢复。

这条规则比增加随机干扰食物更重要。分类练习放在独立的分类模式中完成。

### 食材首先要容易辨认

食材插画的目标是让幼儿联系日常食物，不是追求装饰效果。大虾需要有明显的弯曲身体、头、眼睛、触须和分节；排骨需要表现肉块和只从边缘露出一点的短白骨头。

食材从最初的水饺、大虾、鸡翅扩展为水饺、大虾、排骨、西蓝花、青菜、香菇和包子。鸡翅曾因图形不够清楚被替换成排骨。每次新增或重画食物，都要先回答“孩子不看文字能否认出来”。

### 食谱可以丰富，单屏负担不能随之增加

点餐一次只出现一种目标食物。分类和自由厨房每轮只从七种食材中选择三种。新增食材不应让一屏同时出现更多类别，也不能缩小触摸区域。

## 当前产品边界

- 当前版本无账号、无业务后端、无广告、无内购，也不接第三方行为分析。
- 录音、设置和游戏记录只保存在当前浏览器或桌面入口中。
- 两台设备通过导出、传递、导入语音包共享录音，目前没有自动同步。
- 声音克隆、语音识别和开放式AI对话不在当前版本内。
- 首版优先保证玩法可理解、操作可完成、反馈温和、声音可靠和自然收尾。
